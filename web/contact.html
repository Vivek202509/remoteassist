Contact

Bug reports and feature requests belong in the issue tracker, where they stay public and traceable. That is the only route that actually works today.

Send a message

Tell us what you were trying to do and what happened instead — that is usually enough to answer in one round trip.

This form cannot send anything yet. Online submission is not enabled: this site is static and the form is not wired to any endpoint. Nothing you type is transmitted or stored. It is kept here so the layout is real for whoever connects it. Until then, use the issue tracker.

Routes that work

A bug or a question: open an issue — searchable, and other people benefit from the answer.

A security finding: use GitHub’s private vulnerability reporting on the repository if it is enabled. If it is not, open an ordinary issue saying only that you have a finding and how to reach you — do not put the detail in public.

Deployment help: include the network shape — same LAN, different carriers, corporate NAT — since that decides whether TURN is the answer.

Before you write

  • Troubleshooting guide — black screen, no connection, taps ignored.
  • TURN setup — the fix for “works on Wi-Fi, not on mobile data”.
  • Platform status — what is actually built on Windows.

No address, no phone, no inbox

This page lists no postal address, telephone number or support email, because none exist. Rather than print something plausible, the site prints nothing. Whoever operates a deployment fills these in — see web/README.md for the list of details a real launch still needs.
