Download

Version 1.0 (build 1). RemoteAssist is distributed as source — you build the app and run the broker yourself, which is what makes the “no third party in the middle” claim checkable.

There are no installers on this page. No signed APK and no Windows installer are published anywhere, so every route below is a build from source.

MIT licence, no telemetry Android 8.0 – 15 · API 26–35 Broker: Node.js 18+ 229 protocol + 46 broker checks pass here

Build the Android app

Open android/ in Android Studio (Koala or newer), or build from the command line. You need the Android SDK for API 35 and a JDK — CI builds on 17, and 21 works locally. The Gradle wrapper is committed, so there is nothing to bootstrap.

git clone https://github.com/Vivek202509/remoteassist.git
cd remoteassist/android
./gradlew :app:assembleDebug          # APK in app/build/outputs/apk/debug/

Point it at your broker

Pass the signaling URL on the build command line with -PsignalingUrl. The debug default, ws://10.0.2.2:8080, is the emulator’s alias for host loopback and is not reachable from a physical handset — a phone built with the default will never connect. Use your machine’s LAN address, or a deployed wss:// endpoint.

./gradlew :app:assembleDebug -PsignalingUrl=ws://192.168.1.43:8080

# or, for a broker reachable over the internet
./gradlew :app:assembleDebug -PsignalingUrl=wss://signal.example.com

Cleartext is handled for you. When -PsignalingUrl names a ws:// host, the debug build generates a network-security exception for that one host. Release builds keep the platform default, so no shipped artifact carries a cleartext exemption.

Install on both devices

adb -s <serial-of-host> install -r app/build/outputs/apk/debug/app-debug.apk
adb -s <serial-of-controller> install -r app/build/outputs/apk/debug/app-debug.apk

Permissions you will be asked for

  • Screen capture — the system MediaProjection prompt, once per session.
  • Accessibility service — only on the controlled device, so remote taps and swipes can be injected. Android shows its own disclosure screen.
  • Notifications — the session notification must be visible; it is how the person being helped knows a session is live.

Two devices, please. Screen capture, input injection and NAT traversal cannot be exercised meaningfully on a single emulator. The unit tests run anywhere; the session itself needs hardware — and RemoteAssist has not yet been observed running between two physical Android handsets. The code is complete and its unit tests pass; the device acceptance matrix in the repository is still entirely open.

Optional: device wake

To wake an offline host, add google-services.json to app/, re-enable the Google Services plugin lines in both Gradle files, and set FCM_ENABLED=true on the broker. Without it everything else still works — only wake is inert.

Windows host Preview

Source and developer build only — there is no Windows installer. There is no Windows installer. The host is built from source with the .NET SDK and run from the build output.

The Windows side registers with the broker, pairs cryptographically, captures the desktop with Desktop Duplication, encodes VP8 and accepts remote input. The Windows host streams and accepts input, but no Android controller has rendered its desktop and no session has crossed a network. Treat it as a preview.

cd windows
dotnet restore
dotnet build Techee.Windows.slnx -c Release
dotnet test

What is built and tested

  • TPM-backed device identity, registering against the real broker rather than a mock.
  • Pairing crypto and trust stores (no real-device pairing run yet).
  • DXGI capture → BGRA → I420 → VP8 → WebRTC with DTLS-SRTP, between two in-process peers.
  • SendInput injection with per-command authorisation and rate limiting, verified against a real window receiving real WM_* messages.
  • Authenticated peer recreation instead of a true ICE restart (a SIPSorcery limitation).

Not built, or not yet proven

  • Controller UI — a Windows machine cannot yet drive another device.
  • Unattended host service, power control and scheduling.
  • No Android controller has rendered a Windows desktop.
  • TURN has not been exercised from Windows at all.
  • Display scaling above 100% and multi-monitor selection are unit-covered but untested on hardware.

Before you rely on it: read WINDOWS_ARCHITECTURE.md and the W3 acceptance procedure.

Signaling broker

A small Node.js WebSocket service: it registers devices by public-key id, brokers six-digit codes and paired-direct dials, relays the WebRTC handshake, issues time-limited TURN credentials and optionally sends a wake push. It never sees media.

cd server
npm install
npm test        # protocol conformance + broker end-to-end checks
npm start       # ws://0.0.0.0:8080

That is 229 protocol conformance checks and 46 broker checks. They need no phone and no SDK, which is why they are the part of RemoteAssist you can verify in a minute.

Configuration

Everything is environment-driven; copy server/.env.example and edit. On Node 20+ you can load it directly:

node --env-file=.env src/server.js

TURN, for cross-network sessions

Two phones on different carriers almost always need a relay, because CGNAT blocks direct peer-to-peer. Deploy coturn on a host with a public IP:

sudo apt install coturn
sudo cp infra/turnserver.conf /etc/turnserver.conf
# set external-ip, realm, static-auth-secret (= TURN_SECRET) and TLS certs
sudo turnserver -c /etc/turnserver.conf -v

Open UDP/TCP 3478 and 5349, plus UDP 49152–65535. Verify with a WebRTC trickle-ICE test page before wiring the app.
